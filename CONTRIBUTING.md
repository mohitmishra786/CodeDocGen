# Contributing Guidelines

Thank you for your interest in contributing to CodeDocGen! We welcome contributions from the community.

## How to Contribute

1.  **Fork the Repository**: Create your own fork of the project.
2.  **Create a Branch**: Use a descriptive name for your branch (e.g., `feature/add-rust-ast-parser`).
3.  **Make Changes**: Ensure your code follows the project's style guidelines.
4.  **Run Tests**: Verify your changes by running the existing test suite.
5.  **Submit a Pull Request**: Provide a clear description of your changes and why they are needed.

## Code Style

- Use Black for Python code formatting.
- Follow PEP 8 guidelines.
- Ensure all public functions and classes have descriptive docstrings.
- No emojis should be included in code, comments, or documentation.

## Reporting Bugs

If you find a bug, please open an issue on GitHub. Include:
- A clear description of the bug.
- Steps to reproduce the issue.
- Expected vs. actual behavior.
- Your environment (OS, Python version, etc.).

## Feature Requests

We are always looking for ways to improve CodeDocGen. If you have an idea for a new feature, please open an issue to discuss it.
